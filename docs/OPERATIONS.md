## 배포 전 확인

### 배포 절차: 배포 → `GET /api/health`를 워커 토큰으로 두드린다 → `ok:true`면 저장소가 진짜다

앱에는 워커와 달리 기동 시 환경 검사가 없었다. `SESSION_SECRET` 없이 배포하면
`signSession`이 **요청 시점에** 던져서, 운영자가 보는 것은 로그인 화면의 500 하나뿐이고
어느 변수가 빠졌는지는 알 방법이 없었다. 그래서 진단용 라우트를 뒀다.

```bash
curl -s -H "x-worker-token: $WORKER_TOKEN" https://<앱주소>/api/health
# 정상:   {"ok":true,"missing":[],"recommended":[]}
# 미완성: {"ok":false,"missing":["BLOB_READ_WRITE_TOKEN"],"recommended":[]}
```

**`ok:true`는 저장소가 진짜라는 뜻까지 포함한다.** `BLOB_READ_WRITE_TOKEN`은 배포에서
**필수**다 — 없으면 `lib/store/index.ts`가 파일 저장소로 떨어지는데, Vercel 파일시스템은
요청 사이에 남지 않으므로 그건 대체재가 아니라 수강생의 목소리·캐릭터·프로젝트가
사라진다는 뜻이다. 그런 배포에 초록불을 켜 주면 운영자는 그때부터 다른 데를 본다.
헬스가 없는 것보다 나쁘다. 그래서 거기서는 `ok:false`가 나간다.

로컬은 다르다. 토큰이 없어도 파일 저장소가 **진짜 디스크**를 쓰므로 정상이고,
`ok:true` + `recommended:["BLOB_READ_WRITE_TOKEN"]`이 나간다. 판정은 `VERCEL_ENV`로
가른다(`production`·`preview`는 배포, `development`는 `vercel dev`라 로컬).

| | 토큰 있음 | 토큰 없음 |
|---|---|---|
| **Vercel 배포** | `200 ok:true` | **`503 ok:false`**, `missing`에 이름 |
| **로컬 / `vercel dev`** | `200 ok:true` | `200 ok:true`, `recommended`에 이름 |

나머지 규칙:

- **인증 없는 호출에는 이름을 주지 않는다.** 빠진 변수 목록은 배포의 약한 자리를 그린
  지도다. `{"ok":…}` 하나만 나간다. 인증은 `POST /api/jobs/next`가 쓰는 그 헤더를 그대로 쓴다.
- **값은 어느 쪽에도 실리지 않는다.** 이름뿐이다.
- `WORKER_TOKEN`이 비어 있으면 아무도 이름 목록을 못 본다(`assertWorker`가 무조건 false다).
  그런데 그것 자체가 필수라 인증 없는 응답이 이미 `ok:false`다 — 토큰부터 확인하면 된다.
- **한계**: 프로젝트 설정에서 시스템 환경변수를 통째로 끄면 `VERCEL`·`VERCEL_ENV`가 오지
  않아 배포를 감지할 수 없고, 그때 이 검사는 예전 동작(권장)으로 내려앉는다. 끄지 말 것.

이 라우트는 진단이다. `signSession`/`readSession`의 fail-closed 동작을 대신하지 않는다.

### `BLOB_READ_WRITE_TOKEN` 경로는 실제로 검증되지 않았다

로컬에 토큰이 없어 `blobStore`·`blobArtifactStore`가 **목으로만** 커버돼 있다. 특히:

- **`publish`의 `contentType`** — PNG를 `video/mp4`로 서빙하던 버그를 고쳤는데, 그 수정이 실제 왕복으로 확인되지 않았다. **배포 후 첫 캐릭터 업로드를 눈으로 확인할 것.**
- 이 유형은 **로컬에서 멀쩡하고 배포에서만 깨진다.** `fileArtifactStore`는 `public/` 아래로 복사할 뿐이고 타입을 개발 서버가 확장자로 정하기 때문이다.

### 프리셋 클립아트는 워커 기계에만 있다

앱은 Vercel, 프리셋 이미지는 운영자 Mac의 `~/.codex/skills/character-clipart-library/`에 있다.
카탈로그 **메타데이터**는 `data/preset-clipart-catalog.json`으로 커밋돼 있어 앱과 워커가 같은 키워드 목록을 본다. 이미지 바이트만 워커가 로컬에서 해결한다.

운영자가 캐릭터를 추가하면 `npm run sync:preset-catalog`를 돌려야 앱에도 보인다. 안 돌리면 양쪽이 **일관되게** 그 캐릭터를 모른다(어긋나지는 않는다).

## 수강생 온보딩

### 초대코드 시딩은 한 번에 하나씩

`student-index`는 여전히 공유 배열이고, **시딩만이 유일한 쓰기 주체**다. 두 터미널에서 동시에 시딩하면 한쪽이 유실될 수 있다. 렌더와는 더 이상 경쟁하지 않는다(그게 `students/<id>` 분할의 이유다).

### 코드가 갑자기 안 먹으면

```bash
npm run repair:student-index
```

레코드는 거의 확실히 `students/<id>`에 살아 있고 인덱스만 어긋난 것이다. 이 명령이 `students/`를 훑어 인덱스를 재구성한다. **재발급 전에 이걸 먼저 돌릴 것.**

중복 해시(두 계정이 같은 초대코드)는 **보고만 하고 해결하지 않는다.** 어느 쪽을 살릴지는 사람이 정해야 한다.

## 알려진 한계

### 인덱스 둘은 여전히 공유 배열

`job-index`와 `student-index`는 read-modify-write다. 저장소 계층에 CAS(조건부 쓰기)가 없어 완전히 없앨 수 없다. 대신:

- `job-index` 유실 → **고아 스윕이 30초 안에 복구.** 실측: 경합 72회에서 인덱스 항목 68개가 유실됐고 전부 복구됐다
- `student-index` 유실 → `repair:student-index`가 복구. 자동은 아니다(수강생이 말해야 안다)

완전한 제거는 Postgres 같은 트랜잭션 저장소로 옮기는 것뿐이다. Supabase MCP가 이미 연결돼 있다.

### 인덱스에 보존 정책이 없다

잡이 영원히 쌓인다. 페이지네이션이 들어가 **정확성 문제는 아니고 비용 문제**다. 월 500건 기준으로 한동안 문제없다.

### 캐릭터가 프레임의 32%

본문 텍스트와 캐릭터 머리 사이에 300~470px 빈 공간이 남는다. 키우려면 씬 컴포넌트의 세로 예산을 다시 짜야 하고, 그건 텍스트 공간과의 맞교환이라 프레임을 보고 정할 문제다.

### whisper는 한국어에 쉼표를 찍지 않는다

실측 8/8 세그먼트에서 0개. 따라서 `lib/pipeline/scene-plan.ts`의 쉼표 기반 리스트 규칙은 사실상 사문이고, `list_reveal`은 `첫째/둘째/셋째`로만 발동한다.

### 프리셋 매칭의 동음이의

`사과`(과일/사죄)와 `충격`(충격/놀람)은 여전히 오검출한다. 한국어 동음이의는 길이로 못 푼다. 프리셋은 폴백일 뿐이고 **수강생이 업로드하면 본인이 키워드를 정하므로 정밀도를 본인이 통제한다.**

한 글자 키워드는 라우트에서 거부한다 — `비`가 `준비`·`대비`·`비타민`에 걸리는 것이 프리셋 오검출의 최대 원인이었다.

## 이 저장소에서 반복된 실패 유형

**테스트가 이름이 약속한 것보다 적게 단언한다.** 세 계획에 걸쳐 **아홉 번** 나왔고, 매번 **뮤테이션 테스트로만** 드러났다 — 통과하는 테스트를 읽어서는 알 수 없다.

실제 사례:
- `covers every type listed in SCENE_TYPES`가 `SCENE_TYPES.length === 6`만 검사
- 캐릭터 층위를 고정한다는 테스트가 `padding-bottom:(\d+)px`로 아무 숫자나 통과
- 소프트 실패를 증명한다는 테스트가 `copyClipart`가 resolve한다는 것만 검사
- 소유자 필터를 지워도 아무 테스트도 실패하지 않음(**보안 층이 고정돼 있지 않았다**)
- 키가 죽으면 그 키를 읽던 단언이 폴백을 받아 조용히 공허해짐 — 이 계획에서만 네 번

**대응**: 이제 CI가 자동으로 본다 — `npm run test:mutation`(Stryker, 설정은 `stryker.config.mjs`).
`.github/workflows/ci.yml`의 `mutation` 잡이 돌린다.

- 범위: `lib/**`, `app/api/**/route.ts`, `packages/video/src/utils/**`.
  씬 컴포넌트와 `components/**`는 **일부러 뺐다** — 그쪽은 프레임을 렌더해서 보는 것이지
  단위 테스트로 보는 게 아니라서 뮤테이션이 발견이 아니라 잡음을 낸다.
- 렌더 테스트(`missingCharacterRender.test.ts`)는 뮤테이션 실행에서만 빠진다
  (`vitest.mutation.config.ts`). 34초 스위트 중 31초가 그 파일이고, 뮤턴트마다 다시 도니까
  들어가면 실행 자체가 불가능하다. **일반 테스트 잡에는 그대로 있다.**
- `thresholds.break`는 **래칫**이다. 실측 점수 바로 아래에 두고 **올리기만 한다.**
  빨개지면 임계값을 내리는 게 아니라 살아남은 뮤턴트를 죽이는 테스트를 쓴다.

### 리포트를 읽을 때: 유령 생존자 두 파일

뮤테이션 리포트의 "생존"이 전부 구멍은 아니다. Stryker는 **어느 테스트가 어느 코드를
지나가는지**를 Vite 모듈 그래프로 정하는데, **지정자가 변수인 동적 import는 따라가지 못한다.**
이 저장소에 그런 자리가 정확히 한 군데 있다:

```
app/api/__tests__/voicebox-routes.test.ts:208
  describe.each([...]) 안에서   await import(modulePath)
```

`lib/env.ts`가 import 시점에 env를 스냅샷하기 때문에 그 테스트는 키를 세운 뒤
모듈을 다시 읽어야 하고, 그래서 경로를 변수로 넘긴다. 정당한 코드다. 다만 그 대가로
**두 파일에만** 유령 생존자가 생긴다:

| 파일 | 리포트상 미검출 | 그중 유령 |
|---|---:|---:|
| `app/api/voicebox/preview/start/route.ts` | 42 | **26** |
| `app/api/voicebox/generate/route.ts` | 36 | **25** |

**유령이란 테스트가 실제로는 그 뮤턴트를 죽인다는 뜻이다.** `generate/route.ts`의
소유권 검사를 손으로 지우고 `npx vitest run app/api/__tests__/voicebox-routes.test.ts`를
돌리면 **4개가 실패한다.** 대조 실행(`vitest.related = false`)에서 다른 파일은 전부
±1 이내였다 — **사각지대는 이 두 파일뿐이다.** 나머지 리포트는 믿어도 된다.

그러니 그 두 파일을 보고 "소유권 테스트가 없구나" 하고 테스트를 새로 쓰지 말 것.
이미 있다. 남은 미검출(16·11)은 진짜지만 경계가 아니라 본문 검증과 응답 형태다.

없애려면 그 테스트가 두 라우트를 정적으로 import하면 된다.

### 점수는 하한이지 성적표가 아니다

위 이유로 실측 68.49%의 생존 478건 중 **51건은 유령**이다. 래칫으로는 문제가 없다
(같은 조건에서 재고, 회귀는 그대로 잡힌다). 다만 **68.49%를 스위트의 품질로 인용하지 말 것.**

여전히 유효한 습관: 중요한 동작을 지키는 테스트는 **구현을 망가뜨려 실패하는지 확인**할 것.
그리고 리포트의 생존자는 세 가지가 섞여 있다 — **아무 테스트도 안 덮는 진짜 구멍**,
**다른 가드가 대신 막아 주는 겹방어**(둘을 동시에 지우면 실패한다), 그리고 **유령**.
셋은 대응이 다르고, 테스트를 쓸 값어치가 있는 것은 첫 번째뿐이다.

## 같은 유형의 보안 결함이 세 번 나왔다

1. 클론한 목소리에 `ownerId`가 없어 모든 수강생 피커에 남의 목소리가 떴다
2. 캐릭터 클립아트에 경계를 명시적으로 그어야 했다
3. `/api/learning/insights`에 **세션 검사가 전혀 없었고** `bestPrompt`가 남의 대본 본문을 돌려줬다

**새 저장소를 만들 때 `ownerId`는 편의 필드가 아니라 경계다.** 그리고 키가 소유자를 분리하더라도 **필터를 함께 두라** — 키 구조가 바뀔 때 경계가 조용히 열리는 것을 막는다.
